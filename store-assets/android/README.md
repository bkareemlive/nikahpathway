# Google Play — status and next steps

## What's done (code-level)

- Capacitor added (`capacitor.config.ts`, `@capacitor/core`, `@capacitor/android`,
  `@capacitor/cli`, all pinned to matching v8.5.2 — mixing major versions across these
  breaks the CLI).
- The `android/` native project, generated by `cap add android`.
- App identity: `com.nikahpathway.app`, display name "NikahPathway". **The package ID
  (`com.nikahpathway.app`) is permanent once published — change it now if you want
  something different, not after submitting.**
- Real branding throughout, generated from `src/components/Logo.tsx`'s actual SVG, not
  a placeholder: the launcher icon (all 5 densities, adaptive + legacy + round), and the
  splash screen (all 11 density/orientation variants). Capacitor's default blue "X" logo
  has been fully replaced.
- **Verified**: a debug build (`./gradlew assembleDebug`) compiles successfully end to
  end (93 tasks, `app-debug.apk` produced). This confirms the project itself is sound;
  the two issues hit along the way were Windows-specific and already fixed here, so you
  shouldn't hit them again: (1) Gradle 8.14 doesn't yet support the JDK 25 Android
  Studio bundles, so a separate JDK 21 was used for this build instead — Android
  Studio's own "Run" button handles its JDK selection itself, so this is unlikely to
  come up there; (2) `android/local.properties` needs forward slashes in `sdk.dir`
  (`C:/Users/...`), not backslashes — backslash is an escape character in Java
  `.properties` files, so a backslash path gets silently corrupted. Android Studio
  generates this file correctly itself, so this only matters if it's ever hand-edited.
- `store-assets/android/play-store-icon-512.png` — the 512×512 icon Play Console asks
  for separately from the app itself.
- `store-assets/android/listing.md` — draft store listing copy (short + full
  description, category, content-rating notes, privacy policy link).
- `android/.gitignore` tightened so a signing keystore can never be committed by accident.

**How it works:** this is a native shell, not a rewrite. The WebView loads
`https://nikahpathway.com` directly (`capacitor.config.ts` → `server.url`) — the same
server-rendered site, so it needs no separate build or deployment. Updating the website
updates the app automatically; no Play Store update is needed for ordinary content/code
changes, only for native-level changes (icon, permissions, plugins).

## What you need to do next

1. **Install Android Studio** (bundles the JDK and Android SDK this project needs to
   actually build). This machine has neither right now. https://developer.android.com/studio
2. **Open `android/` in Android Studio** once installed, let it sync, and run the app on
   an emulator or a real device to confirm it loads the live site correctly.
3. **Generate a signing key** (via Android Studio's Build → Generate Signed Bundle, or
   `keytool` once the JDK is installed). Store the keystore file and its password
   somewhere safe outside this repo — `android/.gitignore` already excludes `*.jks` and
   `*.keystore`, but back it up yourself too. **Losing it means you can never publish an
   update to this app again under the same listing.**
4. **Create a Google Play Console account** (console.play.google.com, $25 one-time). An
   organization account needs a D-U-N-S number; a personal account needs a 12-tester,
   14-day closed test before it can publish to production.
5. **Build a signed `.aab`** (Android App Bundle, what Play Store requires) via Android
   Studio, and upload it to a new app listing in Play Console.
6. **Fill in the store listing** using `listing.md` as a draft, upload the icon and
   screenshots (take these from the running app once you can build it), and complete the
   Data Safety form and content rating questionnaire.
7. **Provide a demo account** in the listing submission — reviewers can't test a
   members-only app without one. Use a dedicated test account, not a real member's.
8. **Decide on in-app purchases.** Right now checkout happens through Stripe in the
   WebView, same as the website. Google generally requires Play Billing for digital
   subscriptions sold *inside* the app, though policy on linking out to external payment
   has loosened in some regions recently — worth checking Play's current policy before
   submitting, since this affects review approval.
9. **Push notifications** (optional for launch, but recommended): Capacitor supports
   this via `@capacitor/push-notifications` + Firebase Cloud Messaging, not set up yet.
   Ask if you want this built in before submission.

## I can't do for you

Console account, paying the $25 fee, and actually submitting for review all need to
happen on your end — these are either local-machine installs, an irreversible signing
secret, or account/payment actions I don't do on your behalf.
